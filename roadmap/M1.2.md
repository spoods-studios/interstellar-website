## Phase 55: Craft-Orbital Subcycling Closure — ✅ 2026-07-31

**Goal:** decouple the craft's translational state from the shared 300 s planetary `wh_step` call into a nested, fixed-N, symplectically-derived KDK sub-map inside `run_due_steps()`, closing the M1.1 Rule #7 coast blocker (546 km/orbit + spurious e = 6.07e-4 at step_dt = 300 s) and unlocking 1× real-time launch + fine interactive throttle, with `nbody_force.cpp` byte-untouched and every craft-absent run byte-identical to v1.1.0.
**Requirements:** SUB-01..04.
**Plans:** 5 (11 tasks) + one in-phase research gate (the D-05 perturber-extrapolation sweep, closed before worker integration).

**Delivered:**
- `craft_integrator.hpp` / `physics_craft_integrator.cpp`: the KDK sub-map kernel — half-KICK → `kepler_step` DRIFT → half-KICK, Newtonian(tidal)→J2→1PN kick order, three perturber-sourcing modes (ExactExternal/HoldFixed/KeplerDrift) sharing one implementation with the sweep harness. Nine ground-truth locks including a bit-for-bit two-body reduction to `kepler_step` across 4 conic regimes × 5 N, and a ≤1 ULP pin against `evaluate_force` (`47b1a19`/`6c6b894` RED/GREEN, `91b5b50` sweep harness)
- D-05 resolved by measurement: three-fixture (F1 quiet two-body LEO, F2 Moon-perturbed MEO, F3 J2-dominant LEO) convergence grid, N ∈ {8…16384}. HoldFixed plateaus at 1.0921e-2 m err_extrap (2.8× under the 3.1e-2 m budget, FAILS at every N); KeplerDrift clears at 3.0805e-6 m (4.0 decades under, 3437× better). `kCraftSubstepN = 16384` (accuracy floor N≥1024 + liveness floor N≥16384, larger wins) and `kCraftPerturberMode = KeplerDrift` pinned together (`bed9a43`/`4c38678`)
- Per-substep thrust seam: the M1.1 "mass leads, velocity splits" order preserved at `kCraftDt` cadence; A1 telescoping risk measured, not assumed — 8.34e-10 kg mass-chain deviation and 4.68e-11 m/s (103 ULP) Δv-telescoping deviation over 16,384/81,920 terms, both 2-3 decades under derivation-true bounds (`c1cc1d4`)
- Worker surgery: craft row span-extracted from the planetary integration call (D-01); nested substep loop inside `run_due_steps()`, `CraftBoundaryCache` memoization (~1.7×, 58.09→35.03 ms Release per window), `kCraftFineScaleCap = 2048` calibrated on both lanes (Debug wall budget + the product's warp-entry threshold independently agree) (`304dcba`)
- SUB-01 closure: 546,000 m → 7.363e-5 m one-orbit position error at the same step_dt; spurious e 6.07e-4 → 6.54e-15, measured against a 4×-refined run of the same production path on a J2-carrying fixture so neither the round-off floor nor real J2 oscillation could pass vacuously. 10-orbit drift-band + chunking-exactness locks added (`374eb87`)
- Phase-end gates: Release 1003/1003, Debug 999/999; `nm -u -C` on the new TU clean but for `det_sqrt`/`kepler_step`/`thrust_step`/`j2_pair_accel`/`pn_*`; `git diff v1.1.0 -- engine/src/nbody_force.cpp` empty

**Key decisions:** engine's own Wisdom-Holman KDK split narrowed to one massless test-particle row, not a new numerical method — nested composition stays symplectic (Rein 2020) and the zero-perturber case collapses to `kepler_step` in bits; perturber sourcing resolved empirically per the roadmap's research flag rather than by literature precedent alone (Wisdom 2017 and Saha-Tremaine both pointed the same way the measurement did); `kCraftSubstepN`/`kCraftPerturberMode` locked together since Pitfall C makes them non-independent (truncation error shrinks with N while extrapolation error can plateau); thrust seam shape (a) — `thrust_step` once per burning substep — over shape (b) distributed dosing, because a within-window throttle change makes the outer-window Δv unknowable at window start; RCS translation Δv rides the kernel (not the worker) to preserve the pinned statement order in bits.

**Deviations:** the kick's inverse-square root is `det_sqrt`, not a shared call through `evaluate_force` — DET-03 forbids libm on the trajectory path, so the kernel reproduces `evaluate_force`'s exact op tree with `det_sqrt` substituted, the same substitution the WH interaction kick already makes, with a dedicated 1-ULP lock closing the drift risk that would otherwise open (55-01). Convergence-order lock scoped to F3 only after measurement showed F1/F2 are instrument-floor-dominated at every N in the ladder, which would have made the lock vacuous on those fixtures (55-02). `craft_dt` derived from the live `step_dt` rather than the `kCraftDt` literal, after the trail fixture's 10 s step_dt exposed a 30× fast-forward bug the plan hadn't anticipated (55-04).
