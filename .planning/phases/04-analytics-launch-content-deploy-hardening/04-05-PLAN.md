<objective>
Close the silent-failure window: after every deploy, prove the live site is
serving the bytes that were just built, and turn the workflow red when it is not.

Purpose: SITE-03's second half, via the mechanism D-67 specifies. The site is
entering a low-attention steady state, and the failure being designed against is a
deploy that quietly does not land while nobody is looking. A green deploy step
proves the API accepted an artifact; it does not prove the content-delivery layer
is serving it. The probe closes that gap by requiring the deploying commit's own
stamp in the response body, and failure surfaces through GitHub's default
notification with no extra alerting configuration.

The probe also absorbs the live 404-under-base check deferred from Phase 2, and
confirms this phase's shipped capabilities on the real site: the launch post, the
feed, and the redirect stub.

Output: the full probe route set, the CI job that runs it, and an honest record of
which live checks this phase could certify and which it must defer.
</objective>

    document. The launch-post leg fetches the promoted launch post's URL and
    asserts it carries the same stamp value as the homepage, which proves the post

    an older one. The custom-404 leg requests a path under the base that certainly
    does not exist, capturing the status code and the body separately: the status

    body must carry the stamp. That leg closes the check deferred from Phase 2. The

    response carries the refresh directive.

    pipeline the launch post already proves, and each extra URL is a maintenance
    liability the moment a slug changes.

    Every leg fails the script on mismatch with a message naming the URL and what
    was expected. Never mask a fetch failure by defaulting a captured value to
    something that then compares equal — a failed fetch must fail the probe, not
    silently satisfy it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → public internet | The smoke job issues outbound requests to the deployed site |
| deploy action output → probe argument | A value produced by a third-party action becomes the URL the probe fetches |
| workflow permissions → repository | A new job is added to a workflow that already holds deploy-scoped tokens |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-17 | Spoofing | the freshness verdict | high | mitigate | Success requires the deploying commit's own stamp in the response body; the status code alone is never sufficient, and a cache-busting query defeats an edge-cached stale response |
| T-04-18 | Elevation of privilege | the new CI job | high | mitigate | The smoke job declares no permissions block, so it inherits the workflow's restricted default; the deploy job keeps its existing pages-write and id-token-write scopes and gains only an output declaration |
| T-04-19 | Tampering | probe target sourced from an action output | medium | mitigate | The probe only fetches and greps; it never executes a response, writes a response to disk outside a temporary file, or interpolates a response into a shell command |
| T-04-20 | Denial of service | retry loop in CI | low | mitigate | The retry budget is bounded to roughly three minutes; exhaustion fails the job rather than looping |
| T-04-21 | Repudiation | a failed deploy going unnoticed | high | mitigate | A failed probe exits non-zero, which turns the job and therefore the workflow red, which triggers GitHub's default failure notification — no additional alerting configuration is needed, which is what suits the site's low-attention steady state |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs occur in this plan or phase (04-RESEARCH Package Legitimacy Audit: zero new dependencies). package.json must be byte-identical after this plan |
</threat_model>

## Flagged Assumptions

- **A1 (04-RESEARCH)** — that the deploy action's page URL output for a project
  site is the full base-inclusive URL with a trailing slash. If it is not, the
  probe URLs mis-compose and the smoke job goes red on its first run with an
  obvious log; the fix is one line of YAML. It cannot fail silently.

  environment variable inside the Astro action's composite build step. Plan 04-01
  proved the read works locally; the CI half self-verifies on the first real
  deploy, again visibly rather than silently.
- **The live legs are deploy-dependent by construction.** D-67 asks for exactly
  this, and Phase 3's precedent shows what to do when the platform is degraded:
  record deferred, never assume passed.
