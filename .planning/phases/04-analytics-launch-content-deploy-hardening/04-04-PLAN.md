<objective>
Make a renamed post URL a recoverable event rather than a permanent broken link,
and write the norm down where the agents and the promote flow actually read it.

Purpose: CONT-06. Every Discord embed, RSS guid and vault reference pins a URL.
GitHub Pages offers no server-side redirect configuration, so build-time
meta-refresh stubs from Astro's redirects config (D-65) are the only mechanism
available. The load-bearing detail is that Astro passes string destinations
through verbatim into the stub's refresh URL while applying the base only to the
match side — so a destination written without the base prefix builds cleanly and
sends readers to a path that does not exist. That mistake is invisible without a
test, which is why the map ships seeded with one demonstration entry rather than
empty.

Output: the redirects map with a working demonstration entry, harness assertions
that pin the base-prefix requirement, sweep predicates that keep stubs out of
reader-facing page invariants, and the norm documented in both target files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reader browser → stub page | A published old URL serves a page whose only purpose is to send the browser somewhere else |
| build config → emitted redirect target | A repo constant becomes the destination of an automatic client-side navigation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-13 | Spoofing | open-redirect abuse of a stub | low | accept | The map is a build-time constant in the repository, and Astro rejects external destinations outright for static output — there is no runtime input that can steer a stub |
| T-04-14 | Tampering | HTML injection through a redirect key or destination | low | accept | Astro escapes the template values it interpolates into the stub, and both key and destination are repo-controlled constants rather than user input |
| T-04-15 | Denial of service | a typo'd destination silently serving a stub that leads to a 404 | medium | mitigate | Astro never validates concrete-path destinations, so the harness asserts the emitted refresh target both carries the base prefix and resolves to a file that exists under `dist/` |
| T-04-16 | Information disclosure | stub pages advertised to search engines | low | mitigate | Astro's stub template emits a robots noindex directive natively, and Task 2 keeps stub URLs out of the sitemap |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs occur in this plan or phase (04-RESEARCH Package Legitimacy Audit: zero new dependencies). Redirects are a core feature of the installed Astro version. package.json must be byte-identical after this plan |
</threat_model>
