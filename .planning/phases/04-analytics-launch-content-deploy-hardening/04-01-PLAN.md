<objective>
Build the freshness contract that the rest of Phase 4's deploy hardening stands
on: the build stamps its own commit SHA into every page, and a probe script can
read a served site and tell whether those exact bytes are on the wire.

Purpose: SITE-03's second half ("a post-deploy smoke check verifies the live site
actually updated") is impossible without a marker that distinguishes the new
build from the old one. D-68 makes that marker the commit SHA in page markup. A
naive "HTTP 200 = deployed" check passes against a stale CDN cache — exactly the
silent-failure window this phase exists to close (04-RESEARCH Pitfall 8).

This plan also closes the build-side half of SITE-03 by proving empirically —
not by reading Astro's source — that a frontmatter schema violation crashes the
build loudly.

Output: the SHA stamp in BaseLayout, `tests/live-probe.sh`, and
`tests/hardening.smoke.sh` with stamp-coverage and schema-loud-fail assertions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → public internet | The probe issues outbound HTTP requests to a URL supplied as an argument |
| Build environment → shipped markup | `process.env.GITHUB_SHA` is read at build time and rendered into every page |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Spoofing | `tests/live-probe.sh` freshness assertion | high | mitigate | The probe succeeds only on finding the deploying commit's own SHA in the response body; a 200 status alone is never sufficient, and a cache-busting query param defeats an edge-cached stale response |
| T-04-02 | Information disclosure | build-sha meta tag in public markup | low | accept | The commit SHA is already public — this repo's history is a public GitHub repository; no secret, path or environment value is stamped |
| T-04-03 | Tampering | probe base URL supplied as an argument | low | mitigate | The probe never executes fetched content and never writes to the filesystem from a response; it only greps the body. It is invoked with a URL derived from the deploy action's own output, never user input |
| T-04-04 | Denial of service | unbounded retry loop in CI | low | mitigate | Retry budget is bounded by `PROBE_ATTEMPTS` x `PROBE_DELAY` with a ~3 minute ceiling; exhaustion fails the job rather than looping |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs occur in this plan or phase (04-RESEARCH Package Legitimacy Audit: zero new dependencies). `package.json` must be byte-identical after this plan |
</threat_model>
