<objective>
Give the site cookieless pageview analytics that ship only when the developer has
an account, and that fail loudly the moment the configured value is wrong.

Purpose: ANLT-01. D-60 picks GoatCounter hosted; D-62 puts the script in the
shared layout so the 404 page counts too, turning dead-link traffic into the
cheapest possible radar for the exact failure CONT-06 guards against. D-61 makes
the site code optional-if-unset rather than a hard requirement, because the
account does not exist yet and D-08 means every push deploys — a hard block would
freeze the pipeline and make this phase unable to reach green.

This is deliberately the site's first and only client JavaScript. The existing
zero-JS assertions do not disappear; they tighten into "every script tag on the
site is the one sanctioned analytics tag", which holds in both states.

Output: the gated constant and guard, the script tag, and a test suite that stays
green both now (unset) and after the developer's post-phase signup push (set).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser → third-party CDN | Every page load fetches and executes a script served from GoatCounter's CDN |
| visitor browser → analytics service | The script transmits the visited path to a hosted endpoint |
| build config → shipped markup | A repo constant decides whether the script is emitted at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-09 | Tampering | third-party counter script served from the vendor CDN | high | mitigate | Exposure is bounded to one script with no cookies and no personal data on the site; the D-61 gate keeps it out of the build entirely until the developer deliberately sets the code. Subresource Integrity is not viable because the vendor updates the script server-side, so the residual risk is accepted and recorded here rather than silently ignored |
| T-04-10 | Information disclosure | pageview transmission | medium | mitigate | The chosen service is cookieless and aggregate-only; scope is locked to one pageview script with no events, dimensions or click instrumentation, enforced by the acceptance criteria in Task 2 |
| T-04-11 | Spoofing | a malformed or near-miss site code silently sending data nowhere | medium | mitigate | The guard rejects the placeholder and any value outside the valid site-code character set at config-load time, failing the build and naming the constant |
| T-04-12 | Elevation of privilege | the script becoming a general client-JS foothold | medium | mitigate | The retightened site-wide assertion makes any second script element fail the suite in both constant states |
| T-04-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs occur in this plan or phase (04-RESEARCH Package Legitimacy Audit: zero new dependencies). The counter is a remote script tag, not a dependency. package.json must be byte-identical after this plan |

**Canon referral:** generic consent and data-retention compliance is canon
territory covered by `/gsd-secure-phase`; it is not minted as a bespoke
prohibition here. The bespoke privacy prohibition in `must_haves.prohibitions`
covers the project-specific constraint that there must be nothing to consent to.
</threat_model>
